# 2026-08-30

## 修复 pnpm build 时 wasm 被内联为 base64 的问题

- 根因：`packages/core` 用 Vite 库模式（`build.lib`）构建。Vite 源码中 `shouldInline` 在 lib 模式下无条件返回 true，即 `?url` 引用的资源全部内联成 base64 data URL，`assetsInlineLimit` 被忽略（已验证 vite@5.4.14 源码）。
- 修复：`packages/core/vite.config.ts` 新增 `keepWasmAsFile()` 插件：
  - `load` 钩子拦截 `*.wasm?url`，改用 rollup `emitFile` 输出真实文件，返回 `import.meta.ROLLUP_FILE_URL_<refId>`；
  - `transform` 钩子把 pathkit.mjs 内部 `new URL("pathkit.wasm", import.meta.url)` 兜底同样替换为该引用（否则 350KB wasm 会再内联一次）。
- 结果：`packages/core/dist/pathkit.wasm` 独立文件；`apps/suika/build/assets/pathkit-*.wasm` 独立文件，JS bundle 中零 base64。app 构建时 Vite 会自动把 wasm 拷贝进自己的 assets（非 lib 模式，assetsInlineLimit 正常生效）。
- 注意：开发模式（scripts/dev.js，esbuild watch）仍用 `.wasm: 'dataurl'` 内联，dev 行为不变，属预期。
